# Путь от GITHUB на хостинг

Этап репозитория пройден. Следующая большая стадия - не "залить файлы еще раз", а подключить GitHub-репозиторий к хостингу.

GitHub сейчас хранит код проекта. Но сам по себе GitHub - это не сервер для нашей полноценной игры с логином, паролями, профилями и онлайном. Для простой статической страницы хватило бы GitHub Pages, но у нас есть `server.js`, API, сессии, комнаты, runtime-данные. Значит нужен хостинг, который умеет запускать Node.js.

Дальше схема такая:

1. GitHub остается источником кода.

   Там лежит текущая версия проекта: HTML, CSS, JS, `server.js`, `package.json`, данные, картинки, биографии.

2. Хостинг подключается к GitHub.

   Мы выбираем платформу типа Render, Railway, Fly.io, VPS или другую Node.js-платформу. В настройках хостинга говорим: "возьми код из репозитория `ChessTao/Chess-Legends`".

3. Хостинг скачивает проект к себе.

   Он делает примерно то же, что человек сделал бы командой `git clone`: берет файлы из GitHub и помещает их на свою машину или контейнер.

4. Хостинг устанавливает зависимости.

   Он смотрит на `package.json` и выполняет что-то вроде:

   ```bash
   npm install
   ```

5. Хостинг запускает сервер.

   По нашему проекту это будет примерно:

   ```bash
   npm start
   ```

   А `npm start` запускает:

   ```bash
   node server.js
   ```

6. Хостинг выдает публичную ссылку.

   Например что-то вроде:

   ```text
   https://chess-legends.onrender.com
   ```

   И уже по этой ссылке дети смогут открыть игру.

7. Когда мы меняем код локально, путь обновления такой:

   локальные изменения -> `git commit` -> `git push` -> хостинг видит новый коммит -> автоматически пересобирает и перезапускает сайт.

То есть "онлайн" работает не так, что мы вручную копируем файлы в интернет. Мы один раз связываем GitHub с хостингом, а потом GitHub становится мостом: все, что мы отправляем в репозиторий, хостинг может автоматически подтягивать и публиковать.

Особенно важный момент для нашего проекта: у нас есть не только файлы игры, но и runtime-данные - профили, сессии, комнаты. Они не лежат в GitHub и не должны туда попадать. На хостинге нужно будет решить, где они будут жить: либо во временной папке на первом этапе теста, либо в persistent disk/volume, либо позже в базе данных. Для детского теста можно начать проще, но это надо понимать заранее.
