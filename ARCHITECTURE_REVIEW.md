# Проверка логики и архитектуры проекта

Дата проверки: 2026-05-23.

## Краткий вывод

Проект остается понятным статическим SPA без сборщика: `index.html` содержит экраны, `styles/` - оформление, `data/` и `content/` - данные, `src/` - поведение. Для текущего масштаба это рабочая архитектура, но приложение уже перешло границу "маленького скрипта": `src/script.js` стал главным координатором всего UI, состояния, профилей, навигации, биографий и формы матча.

Основной риск сейчас не в игровой механике, а в смешении ответственности и слабой проверяемости пользовательских сценариев. Следующий устойчивый шаг - выделить навигацию/состояние экранов и матчевые настройки из `script.js`, а затем добавить минимальные браузерные smoke-тесты.

Обновление после проходов правок: состояние приложения вынесено в `src/app-state.js`, навигационные lookup-функции вынесены в `src/screens.js`, логика выбора участников матча вынесена в `src/match-players.js`, профильная форма вынесена в `src/profile-form.js`, инфо-страницы и биографии вынесены в `src/info-pages.js`, а базовые структурные smoke-проверки добавлены в `scripts/smoke-check.js`.

## Текущая структура

- `index.html` - все экраны приложения: заставка, профиль, аккаунт, настройки, игра, инфо-страницы.
- `styles/styles.css` - основная визуальная система, адаптивность, карточки, профиль, игра, инфо-страницы.
- `styles/intro.css` - заставка.
- `data/data.js` - единый источник данных шахматистов: игра, биографии, фотографии, фото-кредиты и настройки сложности.
- `content/biographies/ru|en/*.md` - тексты биографий.
- `src/screens.js` - примитив показа одного активного экрана.
- `src/app-state.js` - чтение и запись `chessLegendsState`.
- `src/setup.js` - чтение и установка выбора типа игры, режима и сложности.
- `src/profile.js` - localStorage-профили, статистика, запись одиночных и матчевых результатов.
- `src/profile-form.js` - вход, регистрация, подсказки имен профилей и режим формы профиля.
- `src/match-players.js` - выбор соперника, гостевой игрок, snapshot участников и валидация матча.
- `src/game-preview.js` - основная игровая механика Memory, счет, таймер, результат.
- `src/intro.js` - шахматная заставка.
- `src/info-pages.js` - инфо-разделы, список биографий и загрузка Markdown-биографий.
- `src/script.js` - точка входа и слой склейки: DOM-ссылки, навигация, состояние, профильная форма, выбор соперника, инфо-страницы, запуск игры.
- `server.js` - минимальный локальный статический сервер.

## Поток состояния

Профили хранятся в `localStorage`:

- `chessLegendsProfiles` - список профилей.
- `chessLegendsActiveProfileId` - активный профиль.
- `chessLegendsProfile` - старый legacy-ключ для совместимости.

Состояние приложения хранится в `chessLegendsState`:

- активный экран;
- настройки игры;
- режим профиля;
- флаг "не выходить";
- выбранные участники матча;
- текущая инфо-страница и предыдущий экран для возврата.

Важно: состояние текущей партии после обновления страницы не восстанавливается. Сейчас refresh с игрового экрана переводит в настройки, что логически безопаснее, чем показывать частично потерянную партию.

## Что выглядит хорошо

- Простая модель без сборщика подходит для локального и статического размещения.
- Модули завернуты в IIFE и экспортируют наружу только `window.ChessLegends...`, поэтому глобальная область не совсем хаотична.
- `profile.js` уже отделяет хранение/статистику от UI.
- `game-preview.js` хранит игровое состояние внутри модуля и умеет корректно останавливать таймер и обработчики через `stopGame()`.
- `server.js` защищает от выхода за корень проекта через `path.relative`.
- Есть `npm run check`, который проверяет синтаксис всех JS-файлов.
- Недавняя логика возврата с инфо-страниц и восстановления текущего экрана после refresh стала концептуально правильнее.

## Главные риски

### 1. `src/script.js` слишком много знает

Файл примерно на 1100+ строк отвечает сразу за:

- DOM-ссылки;
- страну и флаги;
- подсказки профилей;
- сохранение состояния;
- выбор участников матча;
- валидацию матча;
- навигацию экранов;
- биографии и инфо-страницы;
- регистрацию/вход/выход;
- запуск игры.

Это делает каждую небольшую UX-правку рискованной: изменение одного сценария легко задевает другой.

Статус: в основном сделано. Уже выделены:

- `src/app-state.js` - `loadAppState`, `saveAppState`.
- `src/screens.js` - `getActiveScreen`, `getScreenByName`, `getScreenName`, `showScreen`.
- `src/match-players.js` - выбор соперника, guest-поля, snapshot, валидация.
- `src/info-pages.js` - инфо-разделы и биографии.
- `src/profile-form.js` - вход, регистрация, подсказки профилей.

`src/script.js` уменьшился примерно с 1134 до 580 строк и стал ближе к роли координатора.

### 2. Есть риск смешанной/неочевидной кодировки

В терминале часть старых файлов (`README.md`, `ARCHITECTURE.md`, часть прежних JS-файлов) отображалась как mojibake. Новый единый `data/data.js` записан как UTF-8 и заменил старый индекс биографий. Для разработки риск все еще остается в старых документах и модулях:

- поиск по русскому тексту может давать странные результаты;
- будущие правки могут смешать кодировки;
- диффы и ревью становятся менее надежными.

Рекомендация: отдельной задачей привести оставшиеся текстовые файлы и JS к UTF-8 без BOM, затем проверить браузер и `npm run check`.

### 3. Матчевая статистика пока неполная для гостя

Статус: исправлено. Если второй игрок - гость, результат теперь записывается активному локальному профилю, а гостевой игрок не сохраняется.

Это может быть ожидаемым временным решением, но логика UX обычно такая:

- локальный профиль против гостя должен получать победу/поражение/ничью;
- гость не должен сохраняться;
- два сохраненных профиля должны оба получать зеркальные результаты.

Текущее правило:

- локальный профиль против гостя получает победу/поражение/ничью;
- гость не сохраняется;
- два сохраненных профиля получают зеркальные результаты.

### 4. Рейтинг матча только растет

Статус: исправлено. Матчевый рейтинг теперь изменяется по результату: победа добавляет очки, поражение снижает рейтинг, ничья дает минимальный плюс. Нижняя граница рейтинга - 100.

Рекомендация на будущее: если понадобится более честная рейтинговая система, заменить текущую простую дельту на Elo-подобную формулу.

### 5. `innerHTML` используется в нескольких местах

В `game-preview.js` и `profile.js` HTML собирается строками. Часть значений экранируется (`escapeHtml` в игровом счете), но профильная статистика и часть карточек полагаются на контролируемые данные.

Риск сейчас умеренный, потому что данные локальные и в основном из проекта, но профильные имена и страны вводит пользователь.

Рекомендация: для пользовательских данных использовать `textContent`/DOM-сборку или единый `escapeHtml`.

### 6. Нет поведенческих тестов

`npm run check` ловит синтаксис, но не проверяет сценарии:

- вход/регистрация;
- refresh на каждом экране;
- выбор "Два игрока";
- новый игрок против сохраненного профиля;
- возврат с инфо-страниц;
- завершение партии и запись статистики.

Статус: добавлен легкий `npm run smoke` без внешних зависимостей. Он проверяет структуру критичных экранов, порядок подключения модулей и наличие новой матчевой логики.

Рекомендация на будущее: добавить Playwright smoke-тесты для настоящей браузерной проверки кликов и refresh-сценариев.

## Проверка навигации

Текущие ожидаемые правила:

- `Старт` открывает профиль.
- Успешный вход/регистрация открывает настройки.
- `Профиль` из настроек открывает аккаунт.
- `Вернуться` из аккаунта открывает настройки.
- `Выйти` открывает профиль и сбрасывает remembered login.
- `Назад` из игры открывает настройки и останавливает игру.
- Инфо-ссылки открывают инфо-экран и запоминают предыдущий экран.
- `Назад` на инфо-экране возвращает на предыдущий экран; если предыдущим была игра, возврат идет в настройки.
- Refresh на профиле/аккаунте/настройках/инфо-странице оставляет пользователя на соответствующем экране.
- Refresh на игре переводит в настройки, потому что состояние партии не сериализуется.

Логика стала согласованной, но ее лучше вынести из `script.js` и покрыть smoke-тестами.

## Проверка игровой логики

Текущая механика:

- колода строится из случайно выбранных легенд по сложности;
- `Фото - фото` создает две фотокарточки;
- `Фото - фамилия` создает фото + текст;
- ход засчитывается после открытия двух карточек;
- при совпадении пара остается открытой;
- в режиме двух игроков найденная пара оставляет ход текущему игроку;
- при ошибке ход переходит другому игроку;
- стартующий игрок чередуется между партиями для одной и той же пары профилей.

Архитектурно это нормально, но название `game-preview.js` устарело: файл уже содержит основную игру, а не preview.

Рекомендация: переименовать в `game.js` или позже разделить на:

- `game/deck.js`;
- `game/state.js`;
- `game/render.js`;
- `game/rules.js`.

## Проверка профилей

Сильные стороны:

- есть миграция legacy-профиля;
- активный профиль отделен от списка профилей;
- запись результата двум локальным профилям сохраняет активный профиль;
- одиночная и матчевая статистика разведены полями.

Риски:

- гостевой матч не записывает статистику активному профилю;
- `matchRating` семантически не рейтинг;
- часть функций профилей экспортируется, но не используется (`recordSingleResult`, возможно `updateProfile`);
- очистка старых тестовых профилей захардкожена в `handleStartupActions()` через ключ `PROFILE_CLEANUP_KEY`.

Рекомендация: вынести разовые миграции/cleanup в отдельный список миграций с версией схемы, например `chessLegendsSchemaVersion`.

## Проверка данных и контента

Данные игры теперь объединены в `data/data.js`. Для каждой легенды там хранится `id`, фамилия для карточек, полное русское имя, фото, пути к RU/EN биографиям и фото-кредиты. Биографии по-прежнему лежат отдельными Markdown-файлами, что удобно для редактирования текста.

Риски:

- есть фото `29-mamedyarov.jpg`, но Шахрияра Мамедьярова нет в `data/data.js`;
- `PHOTO_CREDITS.md` может рассинхронизироваться с единым JS-источником, если его продолжать поддерживать вручную.

Статус: сделано в `data/data.js`:

```js
{
  id,
  surname,
  fullName,
  photo,
  biographyRu,
  biographyEn,
  credits
}
```

Теперь игра, биографии и авторы фото читают одну структуру. Старый `content/biographies/index.js` удален.

## Минимальный набор smoke-тестов

- Первое открытие показывает заставку.
- Нажатие `Старт` открывает профиль.

- Старт одиночной игры открывает поле и `Назад` возвращает настройки.
