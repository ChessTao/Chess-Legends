# План онлайн-версии

Цель: добавить к проекту возможность играть через интернет, не ломая текущие локальные режимы.

## Два уровня онлайна

### 1. Публикация игры в интернете

Игроки открывают сайт, создают профиль и играют на своем устройстве.

Для этого достаточно разместить текущий проект на Node.js-хостинге:

- Render;
- Railway;
- Fly.io;
- VPS;
- любой сервер с Node.js.

Этот вариант дает сайт, профили и вход с паролем через `server.js`, но не дает общей партии между двумя удаленными игроками.

### 2. Настоящий онлайн-матч

Два игрока подключаются к одной партии через интернет и видят общее игровое поле.

Для этого нужно добавить сетевую механику:

- комнаты;
- код приглашения;
- подключение второго игрока;
- общую колоду;
- синхронизацию открытых карточек;
- очередность ходов;
- серверную проверку совпадений;
- общий результат партии.

## Рекомендуемая архитектура

Текущую одиночную игру лучше оставить локальной, а сетевой режим развивать отдельным автономным контуром.

Новый режим добавить отдельно:

```text
Онлайн-матч
```

Так будет меньше риска сломать уже рабочую игру.

## Сервер

`server.js` должен получить слой онлайн-комнат.

Минимальная модель комнаты:

```text
Room
- id
- code
- players
- status
- settings
- cards
- openCards
- matchedPairs
- currentPlayer
- scores
- moves
- createdAt
```

Сервер должен быть главным источником правды для онлайн-партии.

Клиент отправляет действие, а сервер:

- проверяет, чей ход;
- открывает карточку;
- проверяет пару;
- начисляет очко;
- переключает игрока после ошибки;
- завершает партию;
- рассылает новое состояние обоим игрокам.

## WebSocket

Для онлайн-матча лучше использовать WebSocket.

Минимальные события:

```text
create-room
join-room
room-state
player-ready
open-card
restart-game
leave-room
game-over
error
```

REST API можно оставить для профилей:

```text
/api/register
/api/login
/api/profiles
/api/profiles/save
```

Онлайн-партию лучше не делать через обычный polling, потому что ходы должны приходить второму игроку сразу.

## Клиент

На фронтенде нужно добавить:

- выбор режима `Онлайн-матч`;
- экран создания комнаты;
- экран ввода кода комнаты;
- экран ожидания второго игрока;
- отображение статуса подключения;
- обработку отключения соперника;
- блокировку кликов, когда ходит другой игрок.

Для локальных партий можно оставить текущий `src/game-preview.js`.

Для онлайн-партии лучше сделать отдельный модуль:

```text
src/online-game.js
```

Он должен отображать состояние, пришедшее от сервера, и отправлять действия игрока.

## Профили и статистика

На первом этапе онлайн-матч можно запускать только для вошедших профилей.

Минимальное правило:

- результат онлайн-матча записывается обоим профилям;
- гостевые онлайн-игроки не поддерживаются на первом этапе;
- сервер сам сохраняет результат после завершения партии.

Позже можно добавить:

- гостевые онлайн-матчи;
- историю матчей;
- таблицу лидеров;
- Elo-подобный рейтинг;
- поиск случайного соперника.

## Порядок реализации

1. Опубликовать текущую игру на Node.js-хостинге.
2. Добавить в интерфейс отдельный режим `Онлайн-матч`.
3. Добавить серверные комнаты в `server.js`.
4. Добавить WebSocket-соединение.
5. Реализовать создание комнаты и подключение по коду.
6. Перенести правила онлайн-партии на сервер.
7. Сделать клиентский модуль `src/online-game.js`.
8. Добавить экран ожидания соперника.
9. Добавить синхронизацию ходов и результата.
10. Записывать результат онлайн-матча в профили.
11. Проверить отключение, перезаход и ошибки сети.
12. После стабилизации добавить рейтинги и таблицы лидеров.

## Минимальная первая версия

Первая рабочая онлайн-версия должна уметь:

- создать комнату;
- показать код комнаты;
- подключить второго игрока по коду;
- запустить одну общую партию;
- синхронно открывать карточки у обоих игроков;
- показывать счет и текущий ход;
- завершать матч с победителем или ничьей.

Без этого пока можно обойтись:

- случайный подбор соперника;
- чат;
- аватары;
- история матчей;
- глобальная таблица лидеров;
- сложная рейтинговая формула;
- восстановление партии после долгого отключения.

## Главный принцип

Не переделывать весь проект сразу.

Текущие локальные режимы должны остаться рабочими. Онлайн-матч лучше развивать отдельной веткой логики и подключать к общей системе профилей только там, где это действительно нужно.
