# Шахматные Легенды

Одностраничная игра Memory про шахматистов. Проект работает без сборщика: HTML, CSS, JS, Markdown-биографии и локальные изображения лежат в репозитории.

## Запуск локально

```bash
npm start
```

По умолчанию сервер открывается на `http://127.0.0.1:4173/`.

Локальный сервер нужен для загрузки Markdown-биографий через `fetch()` и для API профилей с паролем.

## Запуск через Docker

```bash
docker compose up --build
```

Контейнер приложения открывается на `http://127.0.0.1:4173/`, рядом поднимается PostgreSQL.

Слой хранения отделен в `server-storage.js`: без `DATABASE_URL` сервер пишет в `.runtime/*.json`, а при наличии `DATABASE_URL` использует PostgreSQL.

Для проверки PostgreSQL-режима локально:

```powershell
docker compose up -d postgres
$env:DATABASE_URL="postgres://chess_legends:chess_legends_password@localhost:5432/chess_legends"; npm start
```

## Проверка

```bash
npm run check
```

Команда проверяет синтаксис серверного файла, всех JavaScript-файлов приложения и запускает структурный smoke-check.

Отдельно можно запустить только smoke-check:

```bash
npm run smoke
```

## Возможности

- Режимы карточек: `Фото - фото` и `Фото - фамилия`.
- Режимы игры: одиночная игра и отдельный экран сетевой игры.
- Сложности: 16, 32, 48 и 64 карточки.
- Локальные профили игроков, страна и флаг.
- Вход/регистрация с паролем через локальный Node API.
- Одиночные рекорды по сложностям: время, ходы, средние значения.
- Матчевая статистика и рейтинг отдельно от одиночной игры.
- Инфо-разделы: правила, биографии, условия фото и авторы фото.

## Данные

Основной источник игровых данных - `data/data.js`.

Он содержит:

- список шахматистов;
- пути к фотографиям;
- пути к RU/EN Markdown-биографиям;
- краткие фото-кредиты для раздела `Авторы фото`;
- настройки сложности.

Биографии лежат в `content/biographies/ru/` и `content/biographies/en/`. Для каждого шахматиста из `data/data.js` должен существовать Markdown-файл в обеих языковых папках.

## Профили

В браузере используются ключи `localStorage`:

- `chessLegendsProfiles`;
- `chessLegendsActiveProfileId`;
- `chessLegendsProfile` для миграции старого одиночного профиля;
- `chessLegendsState`.

При запуске через `npm start` сервер также хранит профили с паролем в `.runtime/profiles.json`. Папка `.runtime/` не предназначена для коммитов.

## Публикация

Для закрытого теста выбран скрытый раздел на `aveskulov.com`: без ссылки с основного сайта и с `noindex`. Поэтому в `index.html` добавлен `robots: noindex, nofollow`.

Для статического размещения нужно публиковать:

- `index.html`;
- `assets/`;
- `content/`;
- `data/`;
- `src/`;
- `styles/`;
- `PHOTO_CREDITS.md`.

Статический хостинг даст игру и локальные профили в браузере, но без серверного входа с паролем.

Если нужен вход с паролем и синхронизация профилей через сервер из репозитория:

```bash
HOST=0.0.0.0 PORT=4173 NODE_ENV=production npm start
```

На Windows PowerShell:

```powershell
$env:HOST="0.0.0.0"; $env:PORT="4173"; $env:NODE_ENV="production"; npm start
```

## Фотографии

Игровые фотографии лежат в `assets/photos/commons/`. Авторы, источники и лицензии перечислены в `PHOTO_CREDITS.md`; этот файл нужно публиковать вместе с сайтом.
