# Путевая карта выхода в онлайн

1. **Зафиксировать текущий прототип**
   Сделать коммит текущего состояния: локальный одиночный режим, серверные комнаты, приватные комнаты, базовая сетевая партия.

2. **Укрепить авторизацию**
   Привязать сетевую комнату не к переданному с клиента профилю, а к серверной сессии игрока. Ходы должны приниматься только от реально вошедшего пользователя.

   В MVP для закрытого теста нет сценария "забыл пароль". Без email/телефона или другого внешнего подтверждения настоящий password reset сделать нельзя: если игрок забыл пароль, он создает новый профиль. Перед более публичным релизом добавить email-подтверждение и восстановление пароля через одноразовый reset-token с коротким сроком жизни.

3. **Сделать восстановление сетевой партии**
   Если игрок обновил страницу или закрыл вкладку, он должен вернуться в свою активную комнату, а не потерять матч.

4. **Обработать выход и обрыв связи**
   Добавить статусы: `connected`, `disconnected`, `left`. Решить, когда партия отменяется, когда соперник ждет, когда засчитывается победа.

5. **Ограничить создание комнат**
   Добавить лимиты: сколько приватных комнат может создать игрок, как часто можно создавать комнаты, когда пустые комнаты удаляются.

6. **Усилить серверную валидацию**
   Проверять все входящие данные: уровень, название комнаты, код, пароль, индекс карточки, статус партии, права игрока.

7. **Сделать устойчивое хранение**
   Перенести профили, сессии и активные партии из памяти/JSON в более надежное хранилище. Минимум: атомарные файлы для комнат и сессий. Лучше: SQLite.

8. **Развести публичные и приватные данные профиля**
   Лидерборд должен видеть только публичные поля. Серверные данные, парольные поля и служебные токены не должны утекать наружу.

9. **Добавить серверную запись рейтинга**
   Рейтинг должен меняться только после серверного завершения партии. Клиент не должен иметь возможности сам прислать себе победу.

10. **Добавить журнал матчей**
    Сохранять историю: кто с кем играл, уровень, счет, дата, результат. Это поможет отлаживать споры и ошибки.

11. **Добавить тесты сетевых сценариев**
    Минимум: создать приватную комнату, войти вторым игроком, сыграть пару ходов, завершить матч, проверить рейтинг.

12. **Проверить два браузера**
    Прогнать руками: Chrome + другой профиль/инкогнито, два разных устройства в одной сети, затем через внешний адрес.

13. **Подготовить production-сервер**
    VPS или хостинг Node.js, домен, HTTPS, автозапуск процесса, логирование ошибок.

14. **Добавить переменные окружения**
    `PORT`, `HOST`, секрет сессий, путь к базе/хранилищу, режим `production`.

15. **Настроить безопасность HTTP**
    HTTPS, secure cookies, `SameSite`, базовые security headers, ограничение размера запросов.

16. **Сделать резервные копии**
    Автоматический backup базы/профилей, чтобы не потерять пользователей и рейтинги.

17. **Провести закрытый тест**
    Дать ссылку 2-5 людям, собрать ошибки: вход, комнаты, зависания, мобильная верстка, результат партии.

18. **Исправить найденное**
    Закрыть критические баги: потеря партии, неверный ход, сломанный рейтинг, проблемы входа.

19. **Открыть публичный доступ**
    Выкатить стабильную версию на домен, проверить регистрацию, вход, сетевую партию и лидерборд.

20. **После запуска**
    Следить за логами, ошибками, пустыми комнатами, нагрузкой и жалобами игроков.
