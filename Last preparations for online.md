# Last preparations for online

Перед выходом в онлайн осталось не "дописать всё", а довести MVP до состояния, где его не страшно дать людям.

## Самое важное перед публичной ссылкой

1. **Прогнать реальный тест в двух браузерах**

   - регистрация двух разных аккаунтов;
   - вход в публичную комнату;
   - создание приватной комнаты;
   - вход вторым игроком по коду и паролю;
   - несколько ходов;
   - завершение партии;
   - refresh во время ожидания и во время матча;
   - закрыть вкладку и вернуться.

2. **Запускать сетевой smoke/e2e тест перед деплоем**

   Тест уже добавлен: `scripts/online-smoke-check.js`.

   Запуск:

   ```bash
   npm.cmd run online-smoke
   ```

   Он проверяет регистрацию двух игроков, серверные сессии, приватную комнату, вход второго игрока, старт партии, запрет хода вне очереди, корректный ход и восстановление активной комнаты.

3. **Проверить runtime-хранилище после рестарта**

   Нужно руками или тестом:

   - запустить сервер;
   - создать комнату;
   - начать матч;
   - перезапустить Node;
   - убедиться, что игрок может восстановиться через `/api/online/active`.

4. **Настроить production-запуск**

   Минимум:

   - `NODE_ENV=production`;
   - `HOST=0.0.0.0`;
   - `PORT`;
   - HTTPS через платформу/прокси;
   - persistent disk для `.runtime`;
   - автозапуск процесса.

5. **Сделать backup `.runtime`**

   Там теперь профили, сессии, комнаты. Перед публичным тестом нужен простой backup-файл или копирование папки по расписанию.

6. **Проверить мобильную верстку онлайн-экрана**

   Особенно:

   - список комнат;
   - приватная комната;
   - игровое поле на 32/48/64 карточки;
   - экран результата.

7. **Проверить логи и ошибки**

   Сейчас сервер минимальный. Перед онлайном полезно хотя бы писать ошибки API в лог, чтобы понимать, что произошло у тестировщиков.

8. **Закрытый тест на 2-5 человек**

   Это последний рубеж: дать ссылку нескольким людям, попросить играть с разных устройств и записать баги.

## Не обязательно до первого закрытого теста

- WebSocket вместо polling.
- SQLite вместо JSON.
- сложный рейтинг/Elo;
- матч-история;
- случайный подбор соперника;
- чат.

## Следующий лучший шаг

Добавить логирование ошибок API в `.runtime/server-errors.log`, чтобы во время закрытого теста было понятно, что произошло у тестировщиков.

## Проверка Firefox и Safari перед релизом

Перед публичной ссылкой отдельно прогнать acceptance-тесты не только в Chrome/Edge, но и в Firefox/Safari:

- регистрация, вход, выход и повторный вход в профиль;
- открытые комнаты: статус "Свободно / Ждет 1/2 / Идет партия";
- приватные комнаты: создание, код входа, пароль, подключение второго игрока;
- сетевая партия: несколько ходов, задержка отображения хода во втором браузере, завершение;
- реванш: оба порядка нажатия кнопки, повторный клик после старта реванша;
- refresh во время ожидания, во время партии и на экране результата;
- подгонка карточек на всех уровнях и в обоих типах игры;
- мобильная верстка, особенно `100dvh`, высота игрового поля, скролл лобби и результат.

Риски:

- Safari/iOS может иначе вести себя с `100dvh`, cookies/localStorage и private browsing;
- Firefox нужно отдельно проверить на `crypto.subtle`, `AbortController`, `replaceChildren`, `Intl.DisplayNames`;
- старые браузеры не поддерживаются, проект рассчитан на современные версии.
