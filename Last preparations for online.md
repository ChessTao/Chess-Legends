# Last preparations for online

Перед выходом в онлайн осталось не "дописать всё", а довести MVP до состояния, где его не страшно дать людям.

## Самое важное перед публичной ссылкой

1. **Прогнать реальный тест в двух браузерах**

   - регистрация двух разных аккаунтов;
   - вход в публичную комнату;
   - создание приватной комнаты;
   - вход вторым игроком по коду и паролю;
   - несколько ходов;
   - завершение партии;
   - refresh во время ожидания и во время матча;
   - закрыть вкладку и вернуться.

2. **Добавить сетевой smoke/e2e тест**

   Сейчас `npm run check` проверяет структуру, но не имитирует два клиента. Нужен хотя бы один серверный тест сценария: создать двух пользователей, создать/войти в комнату, сделать ходы, проверить результат.
   Для твоего проекта такой тест мог бы делать примерно это:

Запустить сервер.
Зарегистрировать игрока A.
Зарегистрировать игрока B.
Игрок A создаёт приватную комнату.
Игрок B входит по коду и паролю.
Сервер создаёт общую партию.
Игроки делают несколько ходов через API.
Проверяется, что:
ход не может сделать чужой игрок;
карточки открываются синхронно;
счёт меняется на сервере;
состояние комнаты одинаково для обоих;
после завершения результат записывается в профили.

3. **Проверить runtime-хранилище после рестарта**

   Нужно руками или тестом:

   - запустить сервер;
   - создать комнату;
   - начать матч;
   - перезапустить Node;
   - убедиться, что игрок может восстановиться через `/api/online/active`.

4. **Настроить production-запуск**

   Минимум:

   - `NODE_ENV=production`;
   - `HOST=0.0.0.0`;
   - `PORT`;
   - HTTPS через платформу/прокси;
   - persistent disk для `.runtime`;
   - автозапуск процесса.

5. **Сделать backup `.runtime`**

   Там теперь профили, сессии, комнаты. Перед публичным тестом нужен простой backup-файл или копирование папки по расписанию.

6. **Проверить мобильную верстку онлайн-экрана**

   Особенно:

   - список комнат;
   - приватная комната;
   - игровое поле на 32/48/64 карточки;
   - экран результата.

7. **Проверить логи и ошибки**

   Сейчас сервер минимальный. Перед онлайном полезно хотя бы писать ошибки API в лог, чтобы понимать, что произошло у тестировщиков.

8. **Закрытый тест на 2-5 человек**

   Это последний рубеж: дать ссылку нескольким людям, попросить играть с разных устройств и записать баги.

## Не обязательно до первого закрытого теста

- WebSocket вместо polling.
- SQLite вместо JSON.
- сложный рейтинг/Elo;
- матч-история;
- случайный подбор соперника;
- чат.

## Следующий лучший шаг

Сделать сетевой e2e/smoke тест на два аккаунта. Он быстро покажет, насколько текущий онлайн действительно живой, а не только "зелёный по синтаксису".
