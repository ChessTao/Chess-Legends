# Архитектура проекта

## Общая идея

`Шахматные Легенды` - простое SPA без сборщика и фреймворка. Страницы описаны в `index.html`, стили лежат в `styles/`, поведение разделено на обычные `<script>`-файлы в `src/`.

JavaScript-файлы не используют `type="module"`. Каждый модуль завернут в IIFE и экспортирует наружу только нужный объект через `window.ChessLegends...`.

## Основные файлы

### `index.html`

Содержит все экраны:

- заставка;
- вход/регистрация профиля;
- аккаунт;
- настройка игры;
- игровое поле;
- инфо-страницы.

Также подключает CSS и JS в рабочем порядке.

### `data/data.js`

Единый источник данных для игры:

- шахматисты;
- фамилии для карточек;
- полные имена;
- фотографии;
- пути к Markdown-биографиям;
- краткие credits для интерфейса;
- настройки сложности.

Если добавляется новый шахматист, сначала обновляется этот файл, затем добавляются фото и биографии в обеих языковых папках.

### `content/biographies/`

Markdown-контент биографий:

- `content/biographies/ru/*.md`;
- `content/biographies/en/*.md`.

Имена файлов должны совпадать с `id` шахматистов из `data/data.js`.

### `styles/intro.css`

Стили стартовой заставки.

### `styles/styles.css`

Основные стили приложения: профиль, аккаунт, настройки, игра, карточки, результат, инфо-страницы и адаптивность.

### `src/app-state.js`

Читает и сохраняет состояние приложения в `chessLegendsState`.

Состояние включает текущий экран, настройки игры, режим профиля, флаг `Не выходить`, выбранных участников матча и состояние инфо-страницы.

### `src/screens.js`

Отвечает за поиск экранов и показ одного активного экрана.

### `src/setup.js`

Работает с выбором:

- типа карточек;
- режима игры;
- сложности.

### `src/profile.js`

Отвечает за профили, статистику и серверный профильный API.

Хранение:

- локальные профили в `localStorage`;
- legacy-миграция из `chessLegendsProfile`;
- серверные профили через `/api/register`, `/api/login`, `/api/profiles`, `/api/profiles/save`.

Статистика:

- одиночные партии отдельно от будущей сетевой статистики;
- рекорды по сложностям;
- матчевый рейтинг;
- поля матчевой статистики сохраняются в профиле как задел под сетевые партии.

### `src/profile-form.js`

Управляет формой входа/регистрации: режим формы, подсказки имен, проверка пароля и переход в настройки после успешного входа.

### `src/game-preview.js`

Историческое имя файла; сейчас это основной игровой модуль Memory.

Отвечает за:

- создание колоды;
- перемешивание карточек;
- отрисовку поля;
- клики по карточкам;
- таймер одиночной игры;
- результат партии;
- остановку таймера и обработчиков через `stopGame()`.

### `src/info-pages.js`

Управляет инфо-разделами:

- правила;
- биографии;
- условия использования фото;
- авторы фото.

Биографии загружаются из Markdown-файлов через `fetch()`, поэтому для полноценной проверки нужен локальный сервер.

### `src/intro.js`

Отвечает за стартовую заставку.

### `src/script.js`

Точка входа и координатор приложения.

В нем остаются:

- DOM-ссылки;
- инициализация модулей;
- список стран и флаги;
- переходы между экранами;
- запуск игры;
- связь результата партии с профилем;
- восстановление состояния после refresh.

### `server.js`

Минимальный Node-сервер.

Он:

- отдает статические файлы проекта;
- запрещает выход за корень проекта;
- выставляет базовые HTTP-заголовки;
- обслуживает профильный API;
- хранит серверные профили в `.runtime/profiles.json`;
- держит сессии в памяти процесса.

## Поток экранов

1. Игрок видит заставку.
2. Нажимает `СТАРТ`.
3. Открывает экран профиля.
4. Входит, регистрируется или использует локальный профиль.
5. Открывает настройки игры.
6. Выбирает тип карточек и сложность.
7. Запускает партию.
8. После завершения видит результат.
9. Может вернуться в настройки, сыграть снова или открыть аккаунт.

Refresh на игровом экране возвращает в настройки, потому что состояние текущей партии не сериализуется.

## Хранение данных

`localStorage`:

- `chessLegendsProfiles` - список локальных профилей;
- `chessLegendsActiveProfileId` - активный профиль;
- `chessLegendsProfile` - legacy-ключ для миграции;
- `chessLegendsState` - состояние экранов и настроек.

Файловое хранение сервера:

- `.runtime/profiles.json` - профили, зарегистрированные через пароль.

Сессии сервера хранятся в памяти, поэтому перезапуск Node-сервера сбрасывает активные серверные сессии.

## Правила развития

- Новые шахматисты добавляются через `data/data.js`, фото и Markdown-биографии.
- Новые экраны должны проходить через `src/screens.js`.
- Изменения настроек игры лучше держать в `src/setup.js`.
- Логику профилей и статистики держать в `src/profile.js`.
- Игровую механику держать в `src/game-preview.js` или позже переименовать/разделить этот модуль.
- Пользовательский текст, попадающий в HTML-строки, нужно экранировать или собирать через DOM API.

## Текущие технические риски

- `styles/styles.css` крупный и со временем может потребовать разделения.
- `src/game-preview.js` называется как preview, хотя содержит основную игру.
- Часть UI собирается через `innerHTML`; для пользовательского ввода безопаснее использовать DOM API или экранирование.
- Сервер профилей минимальный: без базы данных, без персистентных сессий и без полноценной production-авторизации.
