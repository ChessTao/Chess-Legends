# Архитектура проекта

## Общая идея

Проект сделан как простое одностраничное приложение без сборщика и фреймворка.

Все экраны находятся в `index.html`, стили лежат в `styles/`, поведение разделено на несколько JavaScript-файлов в `src/`. Проект рассчитан на запуск через локальный сервер, чтобы пути к скриптам, стилям и фотографиям работали так же, как на сайте.

## Структура файлов

### `index.html`

Главная HTML-разметка приложения.

Содержит экраны:

- заставка;
- вход/создание локального профиля;
- аккаунт игрока;
- настройка игры;
- игровое поле Memory;
- модальное окно результата партии.

Также подключает CSS и JavaScript-файлы в нужном порядке.

### `styles/intro.css`

Стили заставки.

### `styles/styles.css`

Основные стили приложения:

- экраны профиля и аккаунта;
- экран настройки игры;
- игровой экран;
- карточки Memory;
- панель счета;
- результат партии;
- адаптация под размер экрана.

### `data/data.js`

Данные проекта:

- список шахматистов;
- пути к фотографиям;
- настройки сложности.

Этот файл не управляет интерфейсом и не содержит игровой логики.

### `src/screens.js`

Отвечает за переключение экранов.

Главная функция:

- `showScreen(screen)` - показывает выбранный экран и скрывает остальные.

### `src/setup.js`

Отвечает за выбор настроек игры.

Содержит:

- получение выбранного типа карточек;
- получение выбранного режима;
- получение выбранной сложности;
- переключение активного состояния кнопок.

### `src/profile.js`

Отвечает за локальный профиль и статистику.

Профили хранятся в `localStorage`.

Сейчас есть слой нескольких локальных профилей:

- имя;
- страна;
- матчевый рейтинг;
- матчевый счет;
- статистика одиночных игр по сложностям;
- рекорды времени и ходов;
- средние значения за все время и за последние 5 одиночных игр.

Старый одиночный профиль из `chessLegendsProfile` автоматически мигрирует в список профилей.

Публичные операции профильного слоя:

- `listProfiles()`;
- `createProfile(profileData)`;
- `getProfile(profileId)`;
- `updateProfile(profileId, patch)`;
- `recordSingleResult(profileId, result)`;
- `recordMatchResult(player1Id, player2Id, result)`.

Для режима `Два игрока` уже есть UI выбора двух участников матча. Текущий активный профиль продолжает использоваться для обычной одиночной игры.

### `src/game-preview.js`

Отвечает за игровую партию Memory.

Содержит:

- создание колоды;
- отрисовку карточек;
- обработку кликов по карточкам;
- подсчет ходов;
- таймер одиночной игры;
- счет режима `Два игрока`;
- определение результата партии;
- вызов `onGameComplete(result)` после завершения.

Название файла историческое: сейчас это уже не только preview, а основной игровой модуль.

### `src/intro.js`

Отвечает за заставку.

### `src/script.js`

Точка входа и связующий слой приложения.

Содержит:

- ссылки на DOM-элементы;
- инициализацию заставки, настроек, профиля и списка стран;
- переходы между экранами;
- восстановление состояния из `localStorage`;
- запуск партии;
- передачу результата партии в профиль;
- отображение текущего игрока и флага.

Этот файл связывает остальные части проекта, но его важно не превращать в место для всей игровой и профильной логики.

### `server.js`

Минимальный локальный сервер для проверки игры в условиях, близких к сайту.

## Поток экранов

1. Игрок видит заставку.
2. Нажимает `СТАРТ`.
3. Открывается экран профиля.
4. Игрок создает профиль, входит в сохраненный профиль или выбирает гостевой режим.
5. Открывается экран настройки игры.
6. Игрок выбирает тип карточек, режим и сложность.
7. Нажимает `НАЧАТЬ ИГРУ`.
8. Открывается игровое поле.
9. После завершения показывается результат.
10. Через кнопку `Профиль` игрок попадает на страницу аккаунта.

## Варианты игры

Типы карточек:

- `Фото - фото`;
- `Фото - фамилия`.

Режимы:

- `Один игрок`;
- `Два игрока`.

## Текущая модель статистики

### Одиночная игра

Одиночная игра не влияет на матчевый рейтинг.

По каждой сложности сохраняются:

- количество одиночных партий;
- лучшее время;
- лучший результат по ходам;
- среднее время за все время;
- среднее количество ходов за все время;
- среднее время за последние 5 игр;
- среднее количество ходов за последние 5 игр.

### Матчи

Матчевая статистика отделена от одиночной.

Сейчас есть поля:

- матчевый рейтинг;
- количество матчей;
- счет матчей;
- ничьи;
- матчевые поля по сложностям.

Полноценная запись результата двум разным профилям еще не реализована.

## Хранение данных

Сейчас используется `localStorage`.

Ключи:

- `chessLegendsProfiles` - список локальных профилей;
- `chessLegendsActiveProfileId` - текущий активный профиль;
- `chessLegendsProfile` - старый ключ одного профиля, оставлен для миграции и совместимости;
- `chessLegendsState` - состояние экрана, настройки игры и флаг автологина.

Для режима вдвоем используются участники матча:

- `matchPlayer1Id` - первый участник матча;
- `matchPlayer2Id` - второй участник матча.

## Правила развития проекта

### Данные отдельно от логики

Новые шахматисты, фотографии и настройки сложности добавляются в `data/data.js`.

### Переключение экранов отдельно

Если появятся новые экраны, их переключение должно проходить через `src/screens.js`.

### Логика выбора отдельно

Изменения, связанные с выбором режима, сложности или типа игры, лучше добавлять в `src/setup.js`.

### Профили отдельно

Операции с профилями и статистикой должны жить в `src/profile.js`, а не в `src/script.js`.

Следующий желательный шаг для профилей - улучшить отображение матчевой статистики по сложностям на странице аккаунта.

### Игровая логика отдельно

`src/game-preview.js` сейчас содержит основную игровую механику. Если файл начнет разрастаться, его стоит разделить:

- `deck.js` - создание колоды карточек;
- `game-state.js` - состояние партии;
- `game-rules.js` - проверка пар, ходов и победителя;
- `game-view.js` - отрисовка игрового поля и счета.

## Важное замечание по JavaScript

Проект использует обычные `<script>`-файлы без `type="module"`.

Поэтому файлы изолируются внутри самовызывающихся функций и передают наружу только нужные объекты через `window.ChessLegends...`.

Это позволяет запускать проект без сборщика и снижает риск конфликтов имен между JavaScript-файлами.

## Главный архитектурный риск

Сейчас приложение уже имеет слой нескольких локальных профилей и выбор двух участников матча.

Следующий риск - не смешать обычный активный профиль для одиночной игры и пару участников матча в игровом интерфейсе. Игровой экран должен показывать реальные имена и флаги выбранных игроков, а не только подписи `Игрок 1` и `Игрок 2`.
